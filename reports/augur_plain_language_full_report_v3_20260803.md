## 一、這是什麼

Augur 是**一個從零建構出來的世界**。

它的存在理由寫在憲法第一句（永恆條款，任何修憲程序都動不了，原文照錄）：*「Augur exists to faithfully represent reality through persistent identity and traceable evidence, enabling trustworthy intelligence.」*——以持續一致的身分與可追溯的證據，忠實表徵真實世界；**可信的智慧是世界被正確表徵之後自然長出的能力，不是第一目的**。憲法還補一句釐清：忠實不等於完美鏡像——表徵永遠是帶不確定性的近似，忠實性體現於「不確定性可追溯、錯誤可被新證據修正」。

它的建構法分八層：一部憲法（L0）先鑄詞、排序、封死歧路；七層規格依序立起——世界由什麼構成（L1）、萬物如何分類（L2）、每一個是誰（L3）、關於它們的說法怎樣才算可信（L4）、這個世界如何思考（L5）、誰有權伸手改變現實（L6）、這一切棲身在哪塊鐵上（L7）。

而它觀測的對象是**開放的**。憲法把觀測通道開放列舉為「包括但不限於：ERP、MES、Sensor、Document、External Knowledge」；把實體類型例示為工廠、機器、金融工具並列——**在憲法眼裡，金融工具與工廠、機器地位相同，都只是例子**。把第一個域換成氣象或醫療，八層正文一字不必改。台股只是它目前唯一走過的那塊地，不是它的定義。

**四天前（v2 寫成當日）與今天的差別，只有一句話。** v2 說「一切具象全部走同一條路：候選 → 證據通道 → 人類授權門 → 晉升或判死留檔 → 後果回流」——那時候這句話描述的是**設計意圖**。08-02 晚上 19:49，這條路第一次被**引擎自己從頭走到尾**，每一站都留下機器可查的證據。這件事是本版的核心，寫在 §三。

### 3.3 同一段裡必須誠實寫的四件事

**（一）「hugo 逐顆親簽」在資料庫裡沒有留下 hugo 的名字。**
現查【已證實】：`SELECT queue_id,queue_status,decided_by FROM promotion_queue WHERE queue_id IN (555,556,599)` → q556／q599 的 `decided_by` 逐字是 **`evolution_engine`**。`evidence_json` 裡沒有 `decided_by` 欄，只有 `gate_ref='TWEVO-APPLY-go'` 與 `auto_rule='R2-auto-apply'`。

所以留下的證據是「**有人在 shell 打了那三個旗標**」，不是「**機器驗過那個人是 hugo**」。這正是 v2 補注三所說的「誠實上限」——本機沒有代表自然人 hugo 的資料庫角色，AI 與 hugo 都以同一個帳號連線，機器分不出來。配套是**偵測而非預防**（人閘列須帶 `gate_ref` 指向治理提案、週報列出所有宣稱人簽之列供掃視認領）。這個誠實上限在本次里程碑上**完全適用**，必須具名重述。

**（二）人閘是字串常數比對，全檔零 TTY 驗證。**

## 四、三個新長出來的器官

## 六、三個敵人今天長什麼樣（＋第四個）

前身專案死於三件事：**假資料**（沒回的值自己補）、**偷看未來**（用公告前的資料回測）、**自我欺騙**（指標挑好看的講）。用創世紀的語言說，三敵人不是三條工作守則，是**對世界建構法的三種背叛**——假資料背叛「真實優先」、偷看未來背叛知識層的時間機器、自我欺騙背叛認知層的證據鏈與知識層的反自我背書。所以重建時不靠自律、靠機關。**v2 這一章的立論一字不必改。**

但四天的實證把一個 v2 沒有的形狀推上台面，優化計畫書把它逐字寫成組織原則：

> **本專案現階段的主要風險，已經不是「還沒做」，而是「做了、看起來綠了、但量的不是它宣稱在量的東西」。**

**第四個敵人：假綠。** 它與前三個的關係是——**假綠是「自我欺騙」在有了大量機關之後的新形態：機關本身變成了欺騙的載體。** 前三個敵人的解法是「加閘」；第四個敵人的解法**不能**是加閘，因為它就長在閘上。

它的解法是三個問法，依序：
1. **這個綠燈量的，是不是它宣稱在量的東西？**（對帳漏了覆蓋缺口／週更分子分母同時歸零）
2. **這個閘會不會在某些環境下根本沒被執行？**（worktree 缺 venv／掃描器 glob 無命中／目錄改名——三支掃描器目前皆以**空集合＝綠燈**，沒有「至少掃到 N 個對象」的地板斷言。⚠ 撰稿期間，一個並行 session 正在把這條地板做成模組，見 §3.4 末）
3. **回歸鎖唯一有效的驗法＝退回壞版，確認它真的變紅。**

**而這一章最誠實的一句話是**：四天裡機關真的接住了東西——但**接住的大部分是自己前一天犯的錯**，而且**每一次都不是機制自己發現的**，是下一輪對抗鏡頭、或另一個並行 agent、或撞到不一致才回頭發現的。

v2 說「這個世界變強的方式不是模型變聰明，是說錯話變得越來越難」。四天後可以說得更精確：**變強的方式是「昨天的綠燈，今天會被拆開看」——但目前拆開看的是人派出去的鏡頭，不是閘自己會亮紅燈。**

## 八、給接手者的十件事

1. **先讀 `HANDOFF.md`，再讀 `reports/augur_deep_understanding_r4_20260803.md`（證據與覆核指令、20 則踩雷），再讀 `reports/augur_optimization_master_plan_20260803.md`（執行序）。** 但要知道：三份都自陳射程不完整，且都會在數小時內部分過期。

2. **任何數字先問「這是哪一把尺」。** 見 §5.5 的七個一名多義。這不是龜毛，這是本專案四天內至少六次錯誤判斷的共同根因。

3. **看到綠燈先問三個問題**（§六）。特別是第二問——**這個閘會不會根本沒被執行？** 三支掃描器目前都以「空集合＝綠燈」，沒有地板斷言。

4. **「表已建」不等於「義務已履行」。** WM Registry 五個物件在，但逐字判準下完成數是 0。這是本專案最容易誤讀的一類事實。

5. **不要相信文件裡的「硬閘」二字。** 116 支守門程式全部可被一句 session 設定無痕靜音。凡看到「硬閘」，自動翻譯成「在單一 superuser 下是紀律提示」。

6. **`decided_by` / `promoted_by` / `approved_by` 這類欄位，AI 絕不代打。** 這些欄位存在的唯一理由是證明某件事由人做過；一旦 AI 填了，那個保證就變成「我自己能滿足的東西」。這條紀律目前**只活在記憶檔裡，治權層沒有住所**——所以它靠的是你的自覺。

7. **rc=0 不等於通過。** `cmd | tail; echo $?` 取到的是 tail 的 rc。同一支工具的兩個子命令 rc 可能相反。回歸鎖的唯一有效驗法是**退回壞版確認變紅**。

8. **在 worktree（分身工作區）裡工作要格外小心。** hook 的洞今天 11:00 修好了，但三個 worktree 讀到的規則書仍是 v1.31／v1.32（main 是 v1.35），其中 v1.32 那份**仍以生效文字載著已被明示反向廢止的條文**。新增的同步哨會告訴你不同步，但**不會自動修**。

9. **報告會在被 commit 之前過期，這是常態不是意外。** 已經發生三次。寫任何報告時，把資料時點寫到**分鐘**，並把「引用前一律現查」寫成正式體例句，不是註腳。

10. **這個專案最有價值的資產不是那三顆生產特徵，是那本誠實帳。** 四天裡它抓到自己十二盞假綠、五次 AI 自己犯的錯（其中三次是自己建的防呆機制有洞），全部留檔、不刪、不粉飾。**一個誠實說「我不知道」的欄位，比一百個亮著的綠燈更可信**——身分解析那兩個 UNKNOWN，就是這句話的實證。
