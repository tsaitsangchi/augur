# ai_model_from_scratch_design_plan_20260725 — 從零開始設計 AI 模型:計畫與誠實成本地圖

> 純技術規劃(非治權、非演化系統)。作者知識截點 2026-01——**原理層耐久,具體工具名/版本可能已移動、以官方文件為準**。本機硬體以現況為據(GTX 1650 4GB、Ryzen 5 3600、25GB RAM)。

## 0. 先破除一個會浪費幾週的誤解:「從零」有三種意思,成本差 10^4 倍

| 「從零」的意思 | 實際指 | 本機可行性 | 典型成本 |
|---|---|---|---|
| **A. 從零預訓練一個有用的 LLM** | 在數千億 token 上訓練數十億參數 | **不可行**(需數十~數百張 GPU × 數週) | 數萬~數百萬美元 |
| **B. 從零訓練小型任務模型** | 分類器/回歸/小 transformer/embedding,自有標註資料 | **可行** | 數小時~數天、單卡 |
| **C. 教育級從零預訓練** | nanoGPT 級(5–124M 參數、字元或小 BPE) | **可行但慢**(4GB 限死規模) | 數小時~數天、學習價值高、產物無生產力 |

**這份計畫的立場**:若目標是「擁有一個真正有用的語言模型」,誠實路徑是 **微調/續訓現成開源小模型**(不在「從零」定義內,但這是唯一在本機達成「有用」的路);若目標是**理解模型怎麼被造出來、或造一個窄任務專用模型**,B 與 C 都真的做得到。下面把三條路都給完整,你依目標選。

---

## 1. 通用設計生命週期(規模無關,B/C 都適用)

任何 AI 模型的設計紀律是同一套七步,跳步就是後面的坑:

1. **問題框定** — 把「我要一個 AI」翻譯成可量測的輸入→輸出契約(這是分類?生成?排序?回歸?),定義成功指標(不是 loss,是任務指標)與失敗代價。**80% 的失敗在這步已註定。**
2. **資料** — 決定資料分佈、來源、標註、切分(train/val/test 且**時間或實體不洩漏**)。資料量與品質決定天花板,架構只決定你多接近天花板。
3. **基線** — 先做最笨的方法(多數類、線性、n-gram、檢索)。**沒有基線的模型分數沒有意義。**
4. **架構** — 選最小能承載任務的結構;先小後大。
5. **訓練** — 損失函數、優化器、學習率排程、正則、早停;可重現(固定 seed、記錄超參)。
6. **評測** — 在**從未參與訓練/選型**的 held-out 上量任務指標;查過擬合、資料洩漏、汙染。
7. **部署與迭代** — 打包、服務、監控、回饋成下一輪資料。

**貫穿三敵(借用本專案語言,通用適用)**:假資料(合成/補值汙染)、偷看未來(時間洩漏)、自我欺騙(在測試集上調參)。

---

## 2. 資料是真瓶頸(先講,因為多數人先想架構)

- **量的下限**:B 路窄任務,數千~數萬筆標註常足夠;C 路預訓練字元級 GPT,~百萬~千萬 token(整本古騰堡書即可);A 路無下限、只有「更多更好」。
- **品質 > 量**:去重、去汙染(測試集不能在訓練集裡)、標註一致性。**近年小模型的躍進大半來自資料品質工程,不是架構。**
- **切分紀律**:時序資料按時間切、實體資料按實體切(同一股票/用戶不跨切分),否則指標虛高、上線崩。
- **本專案已有的現成資料資產**:`knowledge_*`(論文/文獻語料)、`field_correlation`、`column_catalog`——若要做 B 路的「augur 領域助手小模型」,標註資料可由既有 gold 帳本(`local_model_gold_sample`)供給。

---

## 3. 落到本機硬體:什麼卡死你

- **GTX 1650 4GB**:idle 已被 Windows 顯示吃掉 ~1.2GB,可用 ~2.7GB。這決定「模型參數 + 激活 + 優化器狀態 + batch」必須全部塞進 2.7GB。
  - 訓練記憶體 ≈ 參數 ×(權重 fp16 2B + Adam 動量/方差 fp32 8B)+ 激活。純訓練一個 fp16 模型的 Adam 狀態就吃參數量的 ~10 倍位元組 → **2.7GB 大約撐 ~50M 參數以內、小 batch**,再大就得梯度累積/CPU offload/更省的優化器(8-bit Adam,但那要 CUDA bitsandbytes、4GB 上仍緊)。
- **CPU Ryzen 5 3600(6 核)+ 25GB RAM**:CPU 訓練可行但慢一個數量級;適合 C 路小模型過夜跑,不適合任何趕時間的事。
- **結論**:本機是**學習與窄任務**的機器,不是**造有用 LLM** 的機器。想跨過這條線,務實選項是換一張 12–16GB 的 GPU(如二手 RTX 3060 12GB),那會解鎖 4B 級模型的 QLoRA 微調與更大的從零實驗。

## 4. 三條可行路徑(各附步驟、工具、可驗收里程碑)

### 路徑 B:從零訓練窄任務專用模型(最務實、最快見效)

**適合**:文本分類、意圖偵測、領域 embedding、結構化預測——augur 場景如「問題路由器」「文獻域分類器」。

1. 框定 I/O 契約 + 成功指標(如 F1、Recall@k)。
2. 備標註資料 + 三切分(注意洩漏)。
3. 基線:TF-IDF + 邏輯迴歸 / 多數類。
4. 模型:小 transformer(從零 2–20M 參數)或凍結既有 embedding + 輕分類頭。
5. 訓練:PyTorch;交叉熵/對比損失;AdamW;早停於 val。
6. 評測:held-out 任務指標 vs 基線,**贏基線才算數**。
7. 部署:匯出 → 本地推論(CPU 即可,小模型毫秒級)。

- **工具**:PyTorch、scikit-learn(基線)、sentence-transformers(若走 embedding 頭)。
- **里程碑**:①基線分數落地 ②模型勝基線 ③held-out 無洩漏證明 ④推論延遲達標。
- **本機可行度**:高。單卡數小時或 CPU 過夜。

### 路徑 C:教育級從零預訓練(理解「模型怎麼長出來」)

**適合**:想真的懂 transformer 每一塊、tokenizer、訓練動力學。產物本身無生產力,但這是不可替代的理解。

1. 語料:單一乾淨文本(如古騰堡全集子集、或 augur 的公版哲學語料)。
2. Tokenizer:先字元級(最簡),再小 BPE。
3. 架構:照 nanoGPT(Karpathy,公開)——decoder-only transformer,自己實作 attention/MLP/LayerNorm。
4. 從 5M 參數起,batch 小 + 梯度累積塞進 4GB。
5. 觀察 loss 曲線、過擬合、生成樣本隨訓練演化。
6. 逐步加參數/context,撞硬體牆即止——**撞牆本身是最好的 scaling 直覺課**。

- **工具**:PyTorch;參照 **nanoGPT** repo(最乾淨的教育實作)。
- **可驗收**:①能生成該語料風格的連貫片段 ②親手畫出 loss 對 model size/data 的關係 ③講得出每個張量的形狀與作用。
- **本機可行度**:中(慢但能跑);Scaling laws(Chinchilla:計算最優約每參數 20 token)在小規模也能定性重現。

### 路徑 D:微調現成小模型(嚴格說不是「從零」,但唯一在本機得到「有用 LLM」的路)

**適合**:你真正想要的多半是這個——一個好用的本地助手。

1. 選開源小模型(1.5–4B 級,量化後塞得進 4GB 推論;訓練走 QLoRA)。
2. 備指令/偏好資料(本機已有 gold 帳本雛形)。
3. QLoRA 微調(peft + bitsandbytes;4GB 上 4B 訓練很緊,1.5–1.7B 較穩;或 CPU LoRA 過夜)。
4. 權重轉換鏈:HF safetensors → PEFT 訓練 → 合併/轉 GGUF → ollama 服務。
5. 評測:**部署工作域**的 held-out 金標(不是通用 benchmark)+ 通用能力回歸(防災難遺忘)。

- **工具**:transformers、peft、trl、bitsandbytes、llama.cpp(GGUF 轉換)、ollama(服務)——本機 venv 已裝 peft/trl/gguf,缺 llama.cpp 與 bitsandbytes(CUDA)。
- **誠實限制**:4GB 上 QLoRA 4B 會撞 VRAM(前面算過);1.7B 級較實際,或走 prompt-pack(零訓練,本專案已在做)。
- **本機可行度**:1.7B 級可行、4B 級勉強;硬體升級一步到位。

---

## 5. 評測與陷阱(獨立成節,因為這是最多人栽的地方)

- **測試集汙染**:預訓練/微調資料混進測試題 → 分數虛高。切分前先去重、記錄來源。
- **在測試集上調參 = 自我欺騙**:選型/調超參只能用 val,test 只碰一次。
- **loss ≠ 任務指標**:低 loss 的模型可能任務上更差,永遠量任務指標。
- **小樣本評測不可靠**:n=6 的分數(如本專案 pack eval)是訊號不是結論,要標樣本量、勿當定論。
- **災難遺忘**:窄域微調會磨損通用能力 → 評測須含通用回歸集。

---

## 6. 我的建議(依你可能的真實目標分歧)

- **若目標是「懂模型怎麼造」** → 走 C(nanoGPT),本機夠用,幾週能真懂。
- **若目標是「造一個 augur 專用小工具」**(路由器/分類器/embedding) → 走 B,最快見效、本機綽綽有餘。
- **若目標是「一個好用的本地助手」** → 誠實說這不是「從零」,是 D(微調)+ 現階段的 prompt-pack;且本機硬體是瓶頸,一張 12GB GPU 比任何軟體技巧都有效。
- **不建議**:在 4GB 本機嘗試從零預訓練一個「有用」的 LLM——那不是耐心問題,是數量級問題,會耗掉幾週換來一個玩具。
